# 栈式字节码虚拟机（fan-code + fan-vm）

本文说明 fan-rust 的第二套执行引擎：`fan-code` 把 AST 编译为字节码，
`fan-vm` 在栈式虚拟机上执行。它与 tree 求值器 `fan-eval` 并列，共用同一份
对象系统（`fan-object`）与原生能力（`Runtime`），并通过双引擎对拍持续保证
语义一致。

## 1. 总体架构

```text
                 ┌──────────────→ fan-eval（tree 求值器，直接递归遍历 AST）
fan-parser → AST ┤
                 └──→ fan-code 编译 → ModuleChunk ──→ fan-vm（取指-译码-执行）
                                          │
                                          └── 序列化 → target/**.fanc / .凡码
```

依赖方向是单向的，引擎与编译期严格解耦：

- `fan-code` 只依赖 Rust 标准库，**不引用 AST 之外的执行逻辑、不含任何运行时
  对象**。它的产物 `ModuleChunk` 是纯数据，可直接序列化。
- `fan-vm` **不依赖 parser / AST / fan-eval**，只认识 `ModuleChunk`。运行时值
  复用 `fan-object::Object`；原生内建与 FFI 通过外部注入的 `Runtime` 原生表
  接入，VM 不重复实现宿主能力。
- 模块加载（读文件、解析、递归编译、缓存、环检测）由装配层 `fan-cli` 实现
  `ModuleLoader` trait 后注入，VM 自身不碰文件系统，保持纯粹的取指-执行职责。

## 2. 字节码格式与产物

### 2.1 魔数与版本

定义在 `fan-code/src/chunk.rs`：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `MAGIC` | `b"FANC"`（4 字节） | 编译产物文件头标识 |
| `BYTECODE_VERSION` | `7`（u16） | 字节码格式版本，破坏性变更时 +1 |

加载产物时先校验魔数与版本：版本不符直接拒绝旧产物，回退到源码重新编译，
因此格式演进不会让缓存的 `.fanc` 跑出错误语义。

### 2.2 指令编码

`Opcode` 是 `#[repr(u8)]` 枚举（`fan-code/src/opcode.rs`）：

- 每条指令 1 字节操作码，后接**定宽操作数**，一律小端序、长度前缀；
- 操作数宽度约定：`u8` 用于参数个数等小计数，`u16` 用于常量池/槽位/函数表
  索引，`u32` 用于指令流内的绝对跳转偏移；
- **操作码编号一经发布即固定，新增指令只能追加在末尾、不得重排**，以保证
  产物前向兼容。当前最大编号为 54（`ImportNames`）。

### 2.3 产物落盘

产物不污染源码目录，统一写到项目根的 `target/` 下并镜像源文件相对路径
（`fan-code/src/artifact.rs`）。项目根沿目录上溯、取首个含 `target/` 或
`fan.toml` 的目录；找不到时退化为源文件旁的 `target/`。扩展名映射：
`.fan → .fanc`、`.凡 → .凡码`。

## 3. ModuleChunk：编译期/运行期契约

`ModuleChunk`（`fan-code/src/chunk.rs`）是一个源文件（模块）编译后的完整
产物，全部是可序列化纯数据：

| 字段 | 内容 |
| --- | --- |
| `entry` | 模块顶层语句的入口 `Chunk` |
| `functions` | 全部函数/方法/匿名/分段函数，`MakeClosure` 按索引引用 |
| `classes` | 全部模型（类），`BindClass` 按索引引用 |
| `methods` | 模型方法，`BindClass` 后由 VM 装配进字节码方法表 |
| `interfaces` | 接口纯元数据，链接模块时注册到 `Runtime` 并展平嵌入 |
| `named_types` | 自定义命名/联合类型，链接时注册，支持 `是`/`转为` 与类型名构造 |
| `tags` | 函数声明上的标签（装饰器），`ApplyTag` 按索引引用 |
| `native_exports` | `定义 公开 本地(...)` 的（凡名, Runtime spec 名）别名 |
| `exports` | 导出的顶层绑定名 |

其中：

- `Chunk` = `code: Vec<u8>`（扁平指令流）+ `constants: Vec<ConstValue>`
  （常量池）+ `lines: Vec<u32>`（与每条指令平行的源码行，用于栈追踪）。
- `ConstValue` 只承载可静态序列化的字面量：`Nil/Bool/Int/Float/Byte/Char/Str`。
  运行时对象由 VM 加载时把常量装箱为 `Object`。
- `FunctionChunk` 含 `Arity`（fixed/variadic/optional）、参数与声明类型名
  （供接口签名比对）、函数体 `Chunk` 与 `upvalues` 捕获描述。

反汇编由库 API `fan_code::disassemble` 提供（`disasm.rs`），返回
`DisasmLine` 列表，便于调试与测试断言；当前没有独立的 CLI 反汇编子命令。

## 4. 虚拟机内部结构

`Vm`（`fan-vm/src/vm.rs`）的核心字段：

| 字段 | 作用 |
| --- | --- |
| `modules` / `current_module` | 已链接模块表（主模块固定为 `MAIN_MODULE`），主/子 VM 与加载器共享 |
| `runtime` | `Rc<RefCell<Runtime>>`，全局绑定、原生内建、命名/接口类型的统一入口 |
| `frames: Vec<Frame>` | 调用帧栈，每帧承载指令游标与局部槽位基址（`frame.rs`） |
| `stack: Vec<Object>` | 值栈，绝大多数指令在此弹操作数、压结果 |
| `slots: Vec<Object>` | 每帧独立的局部槽位区，按帧基址切片 |
| `marks` | `...` 展开边界标记，记录压标时刻栈长，供 Marked 系列指令结算 |
| `globals` | 模块全局名表 |
| `functions` | 跨模块共享的字节码闭包登记表 |
| `class_registry` | 已建模型按类名登记，解析嵌入模型与构造期查找 |
| `method_registry` | 模型方法表 `(类名, 方法名) → (模块, 函数索引)` |
| `primitive_method_registry` | 基本类型扩展方法表，键用 `runtime_type_name`（string/array 等） |
| `named_method_registry` | 命名类型扩展方法表，成员访问时优先于底层基本类型同名方法（对齐 tree 顺序） |
| `imported` | 已导入模块公开成员的裸名回退表，按 VM 实例隔离、不跨模块泄漏 |
| `loader` | 可选 `ModuleLoader`，`LoadModule` 时按路径解析 |
| `pending_throw` | 沿调用栈传播的崩溃值，直到某帧 `稍后` 中的 `恢复()` 取走 |

模块文件划分：`vm.rs`（取指-译码-执行主循环与指令分支）、`frame.rs`（帧与
`稍后` 延迟登记）、`upvalue.rs`（闭包捕获）、`ops.rs`（运算语义）、
`loader.rs`（加载 trait）、`vm_function.rs`（闭包登记）、`value.rs`、
`error.rs`。

## 5. 关键运行期机制

### 5.1 闭包与 upvalue

采用 Lua 式 open/closed upvalue（`upvalue.rs`）：

- 帧存活时，upvalue 以 **open** 状态直接引用该帧槽位，帧内对局部变量的赋值
  对所有捕获它的闭包立即可见；
- 帧返回时，被捕获槽位被 **关闭**：值搬进 upvalue 自身存储，闭包在帧销毁后
  仍可读写。

`MakeClosure(u16)` 按函数表索引创建闭包，按 `UpvalueDesc{from_local, index}`
决定从外层局部槽还是外层 upvalue 捕获。

### 5.2 异常与栈展开

- `Throw` 抛出规范错误对象，写入 `pending_throw` 并沿帧展开；
- `RegisterDefer` 登记 `稍后` 零参延迟闭包（已闭合登记时刻的实参与外层变量），
  帧退出时执行；
- `Recover`（对应 `恢复()`）取走当前崩溃值并清空 `pending_throw`，实现恢复。

### 5.3 模型、接口与命名类型

- `BindClass`/`NewInstance` 装配类并构造零值实例；方法在 `BindClass` 后登记到
  字节码方法表，`GetMember` 命中时构造绑定闭包。
- 接口是纯元数据，模块链接时注册到 `Runtime` 并展平嵌入。
- 命名/联合类型在链接模块时由 `register_named_types` 注册：
  - `TypeTest`（`是`）、`TypeCast`（`转为`）复用 `Runtime` 的命名类型信息；
  - `NewNamed` 构造命名类型值；命名类型方法查找优先于底层基本类型方法，
    联合类型在别名上无方法时穿透到底层值。

### 5.4 标签（装饰器）

`ApplyTag(u16, u16, u8)` 处理函数声明上的 `@标签`。标签参数先内联求值到值栈，
运行时构造标签实例并复用零值实例构造路径；`Object::TagContext` 承载标签实例、
当前实现与替换实现。模型上的标签静默忽略。原生处理器经 `resolve_native` 的
「完整 spec 名 → 短名」回退解析（与 `tag.tagRegisterHandler` 等 ext 注册对齐），
VM 加载器侧实现同一套回退。

### 5.5 模块导入与裸名访问

- `LoadModule(u16)` 经注入的 `ModuleLoader` 按路径解析为 `Object::Module`；
  为兼容旧产物，该分支保留。
- `ImportNames(u16 路径常量, u16 别名常量)`（操作码 54）是当前编译器为
  `导入` 生成的指令：绑定模块对象的同时，把模块公开成员登记到 `imported`
  裸名回退表。
- 名字查找顺序：**局部 → upvalue → 已导入模块成员（回退层）→ 全局/原生**。
  模块成员不占局部槽，局部同名静默遮蔽。
- 多个模块导出同名成员时，该裸名进入歧义状态，**运行期首次裸用报错**：
  `名字 X 在模块 [A、B] 中冲突，请用 模块名.X 限定访问`；`模块.成员` 限定
  访问与 `通过 模块 表达式` 不受影响。歧义来源按模块别名去重，同模块重复
  导入不误报。

## 7. 双引擎对拍与质量门

### 7.1 引擎选择

`fan 运行 脚本.凡 [--engine=tree|vm]`，中文别名 `--引擎`，取值 `tree`/`树`
或 `vm`/`虚拟机`，缺省 `tree`。

### 7.2 SDK 双引擎对拍

`fan-cli` 内置 harness `sdk双引擎对拍并量化vm覆盖率`：扫描 `$FAN_SDK/测试`
下所有 `*_测试.凡` / `*_test.凡`，分别用两引擎运行并归类为一致、VM 暂不支持、
输出分歧、VM 运行错误、tree 基线错误。它带三条**硬断言**：

- 输出分歧数为 0；
- VM 运行期错误数为 0；
- tree 基线自身错误数为 0。

「VM 暂不支持」属预期、不计失败，用于量化覆盖率。当前基线为 31/31 文件一致、
暂不支持归零。新增 VM 特性时以该 harness 数据驱动，先消除分歧再推进。

### 7.3 四道门禁

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo build -p fan-cli && ./target/debug/fan 测试 "$FAN_SDK"
```
